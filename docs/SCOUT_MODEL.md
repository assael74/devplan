# מודל הסקאוט

מסמך זה הוא נקודת הכניסה למודל הסקאוט המשותף של DevPlan. הוא מתאר את גבולות
המודל ואת נתיבי הקוד הפעילים, בלי לשכפל את החוקים המפורטים שנמצאים בקוד.

## מקור האמת

המימוש הקנוני נמצא תחת:

```txt
src/shared/scouting
```

נקודות הכניסה הן:

```txt
src/shared/scouting/index.js
src/shared/scouting/players/index.js
src/shared/scouting/teams/index.js
src/shared/scouting/scouting.version.js
```

גרסת המודל המוגדרת בקוד היא `scouting-v2`. קובץ הגרסה קובע אילו שכבות
פעילות ואילו עדיין בתהליך. במקרה של סתירה בין המסמך לקוד, יש לבדוק קודם את
קובץ הגרסה ואת המימוש הקנוני.

## גבולות אחריות

- `src/shared/scouting` מחשב את מודל הסקאוט ואינו אחראי לתצוגה.
- `src/features/playersDatabase/domain` מתאים נתוני קלט, מפעיל את המנוע ובונה
  תחזיות לשמירה.
- שכבת הכתיבה של `playersDatabase` שומרת רק מבנים שאושרו בחוזי הפיצ'ר.
- רכיבי התצוגה מציגים את התוצאה ואינם מחשבים מחדש חוקי סקאוט.
- מסמכי חיפוש ומסמכי Master הם תחזיות ואינם מקור האמת לחישוב או לתיקון.

## מודל שחקן

נקודת התזמור המרכזית היא `buildPlayerScoutState`. התהליך מקבל שחקן, קבוצה
ועונה, מנרמל את הקלט ומרכיב תוצאת סקאוט אחת.

המודל כולל לפי הצורך:

- אותות ופרופילי סקאוט.
- ראיות והסבר לסיווג.
- היררכיית פרופילים, חוזק פרופיל וחוזק המקרה.
- שילובי פרופילים וזרקורים מקצועיים.
- מסלול התפתחות ומסלול מעבר לתחרות עתידית.
- הזדמנות גיוס ורמת דחיפות.
- שאלות אימות, בדיקה ידנית ועניין בשחקן.
- מצב מחזור חיים ומידע מצומצם המיועד לשמירה.

פרופיל סקאוט הוא תוצאה מקצועית מחושבת. הוא אינו מחליף החלטה ידנית של המשתמש
ואינו צריך להיקבע בתוך רכיב תצוגה.

## מודל קבוצה

מודל הקבוצה כולל:

- ביצועים התקפיים והגנתיים ביחס למסגרת התחרות.
- דירוגים, רמות עדיפות והקשר מקצועי.
- צורכי גיוס והזדמנויות ברמת הקבוצה.
- מבנה קווים וסיווג שחקנים בתוך קו.
- זמינות ואיזון של הקבוצה.
- פירוש מקצועי של ביצועי הקווים.

נתוני טבלת הליגה הם מקור האמת לביצועי הקבוצה. נתוני שחקנים יכולים להעשיר את
המודל, אך אינם רשאים לדרוס את ביצועי הקבוצה הרשמיים.

## מצב היישום

לפי `scouting.version.js`:

- שכבת השחקנים פעילה.
- שכבת ביצועי הקבוצה פעילה.
- סיווג קווים ואיזון קבוצה עדיין בתהליך פיתוח.
- קיימים מספרי גרסה נפרדים למודל, לביצועי קבוצה, לסיווג קווים, לאיזון
  ולחוזי השמירה.

אין לתאר את המודל כולו כטיוטה. כאשר משנים שכבה, יש לעדכן את המעמד והגרסה
בקובץ הגרסה ולוודא שהמסמך הזה עדיין מתאר נכון את גבולותיה.

## עבודה נכונה עם המודל

לפני שינוי:

1. לזהות אם השינוי שייך לשחקן, לקבוצה או לחיבור ל־`playersDatabase`.
2. לקרוא את קובץ הגרסה ואת נקודת הכניסה של התחום.
3. לאתר את החוזה או הבונה הקנוני לפני יצירת חישוב חדש.
4. לבדוק את המתאמים והתחזיות המושפעים כאשר משתנה מבנה הפלט.
5. לעדכן חוזי שמירה רק אם מבנה הנתונים הנשמר באמת משתנה.

אין צורך לקרוא את כל קובצי המנוע בכל משימת סקאוט. מתחילים מנקודת הכניסה
ועוקבים רק אחר מסלול הקוד הרלוונטי למשימה.
