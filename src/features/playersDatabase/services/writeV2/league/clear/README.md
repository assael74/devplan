# מחיקת קבוצות ליגה V2

Greenfield: Domain → Prepare → Approval → Receipt → שלבים ידניים → League Audit V2.
אין תלות בכותבי המחיקה הישנים. Player SearchIndex חוסם; אין מחיקתו ב־League.

## בעלות וסדר

League tableRank מתאפס ל־null ו־teamPerformanceContext מוסר לפני האישור, כמו ביצירת עונה. אין הסקת היסטוריית מחיקה מערך null.
כל זוג Team Season / הפניית Root משתנה בטרנזקציה אחת; Root נשמר.
לאחר מכן Team Index, Identity, Clubs, ClubsMaster, LeaguesMaster וביקורת מהשרת.
תחזיות של רשומות היעד מוסרות. שאר העונות והשדות נשמרים.
Receipt קטן מתעד שלב וכשל; Retry מתחיל מהתחלה לאחר קריאה ואישור חדשים באותו Receipt.

## היקף הקריאה והגבולות

הקורא משתמש בסריקות שרת של מסמכי League, Team Season, Root, SearchIndex,
Club ו־ClubsMaster כדי למצוא שאריות גם לאחר שהטבלה נמחקה. זו בחירה מפורשת
לפעולת תחזוקה ידנית במערכת משתמש יחיד; יש להביא בחשבון את עלות הקריאות.
הסריקה אינה כלי Backfill ואינה משנה מזהי מסמכים ישנים.

nextCompetitionPath אינו מכיל seasonKey. כאשר אותו sourceTeamId מופיע גם
בעונה הנשמרת וגם בעונה הנמחקת, ההכנה חסומה כדי לא לנחש בעלות על התחזית.
תחזית Master שנותרה ללא ראיית מקור מספקת מחייבת בדיקה ולא נמחקת בניחוש.

Audit אחרי רענון בודק relations נוכחיים, כולל הפניות שבורות בשנתון ובעונה;
הוא אינו מוכיח לאיזו ליגה השתייך בעבר Root שמסמך עונתו כבר חסר.
באותו סשן מתבצעת גם השוואת before/after של מסמכי הפעולה ושדותיהם המוגנים.
אי־יכולת לבנות Expected מחזירה partial, לא clean.

## ביקורת

Audit ו־Hook. יש להריצן בפרויקט המלא הכולל Firebase, React ומודל הסקאוט המשותף.
