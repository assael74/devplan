# קטלוגי PlayersDatabase

`clubs.catalog.js` הוא מקור המידע הבסיסי לרשימת המועדונים ומשמש להתאמות,
בחירה ותצוגה בזרימות PlayersDatabase. אין ממנו פעולת אתחול או כתיבה גורפת
אל `dbClubs`.

בטעינת ליגה פעילה, זיהוי ובחירה משתמשים ב־`ClubsDirectory` המעודכן מתוך
`ClubProfile`, כולל שמות מקוצרים ואליאסים שנלמדו. תצוגת שמות בעמודי ליגה,
קבוצה ושחקן מעדיפה את הספרייה כאשר הרשומה קיימת. הקטלוג הקבוע אינו דורס
שמות שנערכו בממשק.

שכבות חיצוניות, לרבות מנגנון הסקאוטינג, קוראות את קטלוג המועדונים מהנתיב
הזה ואינן מחזיקות עותק נוסף.

הקטלוג אינו גיבוי ל־Firestore. מידע ידני או מידע שנוצר בתהליכי ליגה, סגל
ונתונים סטטיסטיים נשמר או נבנה מחדש לפי החוזה של בעל המידע.

`teamSignalSummary.catalog.js` מגדיר מבנה מוטמע משותף לסיכום משפחות
האיתותים בארבעת קטלוגי המסמכים הרלוונטיים. הוא אינו קטלוג של מסמך חדש
ואינו מגדיר אוסף נוסף.

בסיס המשחקים של טעינת סטטס מתועד ב־
`TeamSeason.stats.statsLoadState.teamGamePlayedAtLoad` ומוקרן ל־
`League.seasonsById.*.table.teamsById.*.stats.teamGamePlayedAtLoad`.
שני המבנים מוגדרים בקטלוגי המסמכים הקיימים; אין מסמך או אוסף חדש.

`seasonUrl` בבעלות עונת `League` ומוקרן ל־`LeaguesCenter` בלבד. שינויו אינו
קורא או מעדכן אינדקסי שחקנים. `Player SearchIndex.team.seasonUrl` אינו חלק
מהמבנה הפעיל ואינו נכתב בבניית אינדקסים; ערכים ישנים יכולים להישאר ללא ניקוי.

`teamUrl` בבעלות שורת הקבוצה בעונת `League` ומוקרן ל־
`TeamSeason.competitionSnapshot.teamUrl`. עריכת הקישור מעדכנת רק אותם,
ורק אם `TeamSeason` כבר קיים. `Player SearchIndex.team.teamUrl` אינו שדה
פעיל ואינו נכתב או מסונכרן; ערכים ישנים יכולים להישאר ללא ניקוי.

`teamTaskSignals` ו־`teamTaskAvailability` אינם חלק מחוזי הכתיבה הפעילים.
הם עשויים להישאר במסמכים קיימים כמידע ישן שמתעלמים ממנו. המעבר אינו
מפעיל מחיקת שדות; הכותבים מעדכנים רק שדות שבבעלותם ושומרים את יתר התוכן.
